# 疑難排解與營運守則
 
## 1. Session 超時／中斷／context 用盡
 
- **每完成一篇就落盤**：寫 xlsx＋更新「進度追蹤」分頁（ref/DOI/狀態/缺什麼/卡在哪）。中斷後新 session 第一步＝讀進度追蹤分頁，從 pending 續作，絕不重做 done。
- 察覺 context 將盡：停止開新論文，把手上半成品的「已知值＋缺值＋來源線索」寫進「E補值紀錄」分頁，向使用者回報「本輪完成 X、剩 Y、下輪從 Z 續」。
- 單次頁內 JS 有執行逾時上限（常見 45 秒）：大檔下載/解析用「非同步啟動→輪詢 window 狀態變數」拆步。
- 瀏覽器分頁可能被回收（tab 不存在錯誤）→ 重建分頁重新導航，已落盤的資料不受影響。
## 2. 論文鎖住（付費牆）
 
1. 先試使用者 VPN（瀏覽器路線）；同刊有的能開有的不能，逐篇試。
2. 開不了 → 該列標**黑格**（26 特徵全黑），Data_status 寫 `無法讀取(僅摘要,{原因})`，原因寫清楚（付費牆/VPN無此刊權限/Cloudflare）。**摘要能拿到的 PCE 照填**。
3. 通知使用者可行的解法：手動下載 PDF/SI 放入資料夾、換網路環境、或跳過。
4. 使用者提供本地 PDF → 用 pdfplumber 等解析，Notes 標 `[使用者提供SI]`。
5. 黑格解鎖後：清除黑色填色、照常填值、更新 Data_status（曾有黑格列後來完整補齊的先例）。
## 3. CAPTCHA／機器人驗證
 
- **一律停止並通知使用者手動通過**，不得代解或繞過。通過後同一瀏覽器 session 通常整站可用（Elsevier 一次通過可連開多篇）。
- Cloudflare「請稍候」自動盤查（無互動題）→ 等 5–10 秒重試即可，不算 CAPTCHA。
## 4. 常見技術死路（據實回報，不硬撐）
 
| 情況 | 處置 |
|---|---|
| SI 圖為 EMF/WMF（docx 內嵌）或掃描檔 | 機器無法讀取 → 回報，**請使用者提供 PDF 版檔案**（勿收 docx 等難讀格式）或人工讀值 |
| 線上內容與使用者 PDF 差異大 | 停止填值，回報差異，請使用者提供正式 PDF 作唯一依據 |
| 數值只在 UPS 光譜曲線上、無數字標註 | 不估值。Data_status 標 `缺:E`，E補值紀錄註明位置 |
| 全文與 SI 都沒量測某值（如 pvk VBM） | 「文內不可補」寫入紀錄；除非使用者核可跨文獻配對 |
| PDF viewer 無法取文字、Ctrl+F 無效 | 改走「fetch 原始檔＋pdf.js 解析」路線，不要在 viewer 裡纏鬥 |
| 輸出被安全過濾器攔截（含 token 樣式字串） | 清洗輸出（去長雜湊/URL query）、縮小回傳範圍、或只回傳數字 |
| DOI 解析到別篇論文 | 用標題+作者搜尋正確 DOI，修正表格並記錄 |
 
## 5. 向使用者升級（何時該問）
 
- 政策性選擇：跨文獻配對補值、符號慣例、去重取捨、是否收錄邊界案例 → **先問再做**。
- 需要人操作：CAPTCHA、無權限論文、EMF 讀值、實體檔案下載。
- 發現原始資料疑似錯誤（DOI 錯置、組成筆誤、與原論文慣例矛盾）→ 修正＋標紅＋主動回報，不silent fix。
## 6. 品質抽查（交付前）
 
1. 隨機抽 3–5 列紅格，按 Notes 指引重走一次來源，確認可回溯。
2. 用原始基準數據集（若有）比對分佈：E 範圍、PCE 範圍、特徵值域一致性。
3. 跑 SKILL.md 的驗證清單腳本。
4. 交付訊息中：據實列出「已完成／推算（紅）／文內不可補／被擋」四類清單，附各出版社來源連結。
