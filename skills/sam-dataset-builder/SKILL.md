# SAM 數據集建置 Skill

你是數據擷取工作者。任務：從使用者提供的論文（及其 references）擷取每個「元件數據點」，寫成一列，輸出 **xlsx**（顏色承載可信度，不可用純 csv 取代；如需 csv 供 ML 讀取，另行匯出但 xlsx 為主檔）。

**最高原則（依序）：**
1. **絕不猜測**。找不到＝留空＋在 Data_status 標「缺:」。錯的數據比空格傷害大得多。
2. **可信度必須標色**（見下）。使用者要能一眼看出哪格需要人工複查。
3. **Token 效率**：先用關鍵字擷取相關句子，不要通讀全文；每完成一篇立即寫入檔案。

## 工作流程（每篇論文）

```
1. 讀 PDF/網頁 → 判斷收錄與否（見「收錄規則」）→ 不收錄則記錄原因後跳過
2. 決定該論文產生哪幾列（champion、control、不同組成/bandgap 各一列）
3. 文字層擷取：用關鍵字定位句子抓值（見 references/harvesting.md）
4. 缺值 → **主動**抓 SI 解析（文字）→ 仍缺 → 讀圖 → 仍缺 → 留空
5. 立即寫入 xlsx＋上色＋Notes＋Data_status，更新「進度追蹤」分頁，並依「輸出檔名規則」命名
6. 驗證：組成加總=1、E 符號、數值範圍、去重檢查
```

**主動找 SI 原則**：正文數據不全是常態（製程細節幾乎都在 SI）——**不要先問使用者，直接去抓 SI**。只有下列情況才回報：被付費牆/CAPTCHA 擋住、SI 格式機器不可讀（EMF 圖、掃描檔）、或線上讀到的內容與使用者提供的 PDF 差異大（此時請使用者提供 **PDF 版**檔案，勿收 docx 等難讀格式）。

欄位完整規格 → 讀 `references/columns.md`（**寫任何一列之前必讀**）
檢索與解析技術 → 讀 `references/harvesting.md`
疑難排解 → 讀 `references/troubleshooting.md`

## 輸出檔名規則

所有新建或更新的數據檔均使用：

`{年份}_{論文或作者簡稱}_ref{編號或範圍}_{模型}[_{data|dataset}].{xlsx|csv}`

- **必含**：四位數年份、可辨識的論文題名或第一作者簡稱、ref 編號／範圍、實際產出該檔案的模型名稱。
- ref 寫法：單篇用 `ref51`，連續範圍用 `ref51-100`；若資料來自主文且沒有 reference 編號，用 `ref-main`，不可捏造編號。
- 模型名稱採可辨識且適合檔名的短寫，空白改為連字號，例如 `GPT-5.6-sol`、`Fable-5`、`Opus-4.8`。
- `data` 或 `dataset` 可省略；**不得加入** `skill`、`SAM`、`v6`、`ML用` 等與文獻識別、ref 範圍或模型無關的標籤。
- 同一份資料若同時輸出 xlsx 與 csv，兩者使用完全相同的檔名主體，只改副檔名。
- ref 涵蓋範圍改變或改由其他模型重建時，同步更新檔名；不要讓檔名保留過時資訊。

例：`2026_Ullah_Review_ref1-187_GPT-5.6-sol.xlsx`、`2026_Development_of_HTLs_in_inverted_PSCs_ref51-100_Opus-4.8.xlsx`

## 收錄規則

- **收**：p-i-n（inverted）結構之**單接面**電池；SAM 或 SAM 複合（NiOx/SAM、混合 SAM、共摻前驅液）作 HTL；Sn 與 Sn-Pb 系收錄；同篇論文的 champion 與 control 都收；不同鈣鈦礦組成/bandgap 各成一列。
- **不收**：綜述、ML 方法學、市場分析、非 SAM HTL、n-i-p 結構、僅有 tandem 效率而無單接面 PCE 者（tandem 論文中的單接面 p-i-n 數據**要收**）。
- **剔除（變因不在 26 特徵內）**：關鍵變因是添加劑、表面鈍化差異、沉積法差異（dip vs spin 若為比較變因）、元件面積、未知組成之異能隙——若該變因無對應欄位且是該列與他列的唯一差異，不收或註記。已收但後來發現者移至「已剔除_同特徵異PCE」分頁，**不要直接刪除**。
- **去重（同 X 異 f(X)）**：若多個數據點的特徵全同（SMILES＋26 特徵）但 PCE 不同，代表**存在未被 26 特徵記錄到的變因**（如添加劑、批次、面積、鈍化差異）。ML 上 f(X) 必須單值，這種重複只會變成 label noise——**主表只留一個數據點**：取**最高 PCE**（champion 慣例，語意＝該特徵組合的最佳可達效率），其餘整列移至「已剔除_同特徵異PCE」分頁（不刪除）。若能查出造成差異的變因，在被剔除列的 Notes 註明。同一 DOI 出現在多個表 → Notes 標記「合併時擇一」。
- **刪除不收錄列**：需備份到「已刪除_不收錄」分頁再刪，並在紀錄分頁註明**列號位移**（刪列會使其後所有列號改變，舊紀錄的列號引用會失效）。

## 可信度標色（最重要規則）

| 顏色 | 填色代碼 | 意義 | 例子 |
|---|---|---|---|
| **白（無填色）** | — | 抄錄自論文/SI「文字或文字表格」，或確定性計算（mM×MW 換算、正規化） | 主文寫 "HOMO −5.47 eV"；SI Table 文字 |
| **紅** | `FFC7CE` | **需人工二次檢查**：AI 讀圖取值、推算/邏輯推論、原文筆誤之解讀、SMILES 接位/鏈長推測、wash=0「未記載推論」、下限估計值 | 從能階圖讀 −5.79；組成式 Cs0.95 判為 0.05 筆誤 |
| **黑** | `000000` | 論文無法讀取（付費牆/僅摘要）：26 製程特徵全黑，只填編號/DOI/作者/期刊，摘要可得的 PCE 照填 | Data_status 寫明原因 |

判斷基準：**只考慮「擷取流程」的誤差風險，不考慮物理量測不確定度**。文字抄錄＝白；任何需要「看圖、推論、解讀歧義」的步驟＝紅。

## 欄位標頭底色（欄位分類色，與可信度標色無關）

**這是另一套顏色系統**：上面的白/紅/黑是「每個資料儲存格」依可信度上色；這裡是「標頭列（第1列）」依欄位所屬化學類別固定上底色，讓使用者一眼看出欄位分組。新建主表時，第1列每欄依下表套用對應底色（`patternType="solid"`, `fgColor` 用 ARGB hex）；資料列（第2列以後）**不**套用此分類色，資料列的顏色仍只依可信度規則（白/紅/黑）。

| 底色 | ARGB Hex | 涵蓋欄位 | 類別 |
|---|---|---|---|
| 灰 | `FFD0CECE` | NiO2, C60, BCP, PC60BM, PCBM, PC61BM, PEAI, ALD-SnO2 | 元件堆疊材料（HTL底層/ETL，0/1欄） |
| 橘 | `FFFBE5D6` | ethanol, toluene, IPA, THF, chlorobenzene, 2-Methoxyethanol, CH2CL2 | 溶劑（0/1欄） |
| 綠 | `FFE2F0D9` | concentration(mg/ml), E, I, Br, CL | 數值欄：濃度、能階差、X-site鹵素比 |
| 藍 | `FFDAE3F3` | wash | 沖洗步驟（0/1欄，單獨一色） |
| 藍灰 | `FFD6DCE5` | Cs, FA, MA | A-site 陽離子比 |
| 黃 | `FFFFF2CC` | Pb, Sn | B-site（Pb/Sn）比 |
| 粉紫 | `FFFFCCFF` | PCE | 預測目標欄（label），單獨標示 |
| 無填色（白） | — | 編號, SAM/HTL材料名稱, smile, Reference_DOI, Ref_author, Ref_journal, Data_status, Notes | 非26特徵欄（識別/出處/狀態欄） |

套用方式：用 openpyxl 寫入時，對第1列對應欄位設定 `cell.fill = PatternFill(patternType="solid", fgColor="FFD0CECE")`（其餘顏色同理換 hex）。**欄位順序、名稱、分類固定**，新建檔案時直接照此表上色，不需使用者每次重新指定。若使用者要求新增欄位，先詢問該欄位屬於哪個類別（或是否需要新色），再更新本表與「說明_Legend」分頁。

## 專業知識推論分級（哪些欄位可以「推」）

| 級別 | 允許的推論 | 顏色 |
|---|---|---|
| **A 確定性化學/算術（可推，白）** | 前驅鹽莫耳量→化學計量組成比；巢狀組成式展開與正規化；mM×MW 濃度換算；元件 stack 完整列舉→未提及之 ETL/溶劑欄=0；揮發性添加劑（MACl 等）不計入 X-site（照論文組成式記帳，Notes 註記添加劑） | 白 |
| **B 強經驗法則（可推，必紅＋Notes 寫推論鏈）** | dipping 法→wash=1（浸泡後沖洗為標準操作）；**表徵段間接證據**推製程（例：洗滌實驗顯示須清洗才有單層特徵→推 wash=1）；兩溶液體積比→組成；間接敘述→溶劑；筆誤解讀 | 紅 |
| **C 禁止推論（留空）** | E/HOMO/VBM 任何能階值；憑分子類型猜溶劑或濃度；PCE；跨文獻搬值（未經核可） | — |

**B 級鐵律**：間接證據只是候補——**元件製程段（Methods/SI 的 device fabrication）明文永遠優先**。表徵實驗（如 rinse test、穩定性測試）描述的操作不等於元件製程步驟；用它推論時 Notes 必須寫明證據出處（例：`wash=1由Fig.2c洗滌實驗間接推論,非Methods明文`），供人工覆核。

## Notes 欄規則

- **白格列：留空**。不寫「沒問題」「來源是XX」之類。
- **紅格列：每個紅格一段，約 20 字內**，格式＝「欄:查哪張圖/表＋AI 誤差原因」，多段用「；」串接。
  - 例：`E:讀Fig.1F能階圖(讀圖)`、`wash=0未記載推論`、`SMILES:Py3鏈長/接位推斷,查SI`
- 完整的來源與計算過程寫入「E補值紀錄」分頁（audit trail），不塞在 Notes。

## 必備工作分頁

| 分頁 | 用途 |
|---|---|
| 主表 | 數據列 |
| 說明_Legend | 顏色/欄位/規則說明，含「欄位標頭底色」對照表（每次規則變動要同步） |
| E補值紀錄 | 每筆補值的完整來源（DOI、圖表編號、計算式）、pending 清單、政策決定 |
| Notes備份 | 精簡 Notes 前的原始完整註記 |
| 已剔除_同特徵異PCE | 去重移出的列（完整保留） |
| 已刪除_不收錄 | 刪除前備份 |
| 進度追蹤 | 每篇論文：ref 編號/DOI/狀態(done/pending/blocked)/缺什麼/卡在哪 —— **中斷恢復的依據** |

## 驗證清單（每批寫入後執行）

1. Cs+FA+MA＝1、Pb+Sn＝1、I+Br+CL＝1（誤差>0.01 就回查）
2. E 在 −0.7 ~ +1.0 之外 → 回查；E 符號與「SAM HOMO 比 pvk VBM 深(負)/淺(正)」一致
3. 0/1 欄只有 0 或 1；PCE 在 5–27 之間
4. 所有 SMILES 通過 RDKit 解析
5. 紅格列必有對應 Notes；Data_status 的「缺:」清單與實際空格一致（**寫「完整」的列不得有隱藏空格**）
6. 去重掃描：同 SMILES＋同 26 特徵 → 觸發 champion 規則
7. 檔名包含年份、論文／作者簡稱、ref 編號／範圍及實際使用模型，且不含禁止標籤
